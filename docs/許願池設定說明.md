# 許願池留言：Supabase 設定說明

許願池的留言要存在網路上的資料庫，GitHub Pages 本身存不了。這裡用 Supabase 的免費方案。
設定完成前，遊戲在本機（localhost）用假的收件端測試；正式網站上會顯示「留言功能還在準備中」，玩家只能許願、不能留言。

> 畫面上的按鈕名稱是依目前的 Supabase 介面整理的，改版後可能略有不同。找不到時，把你看到的畫面描述給 AI 助理。

## 一、申請帳號與建立專案

1. 到 <https://supabase.com>，按 **Start your project**，用 GitHub 帳號或 email 註冊。
2. 方案選 **Free**（不需要信用卡）。
3. 按 **New project**：
   - **Name**：自訂，例如 `xinzhijian-wishes`。
   - **Database Password**：按產生器產生，**自己保管，不要貼給任何人或 AI 助理**。
   - **Region**：選離台灣近的，例如 Tokyo 或 Singapore。
4. 等專案建立完成（約一兩分鐘）。

## 二、建立資料表與權限規則

1. 左側選 **SQL Editor** → **New query**。
2. 打開倉庫裡的 [`docs/supabase-wishes.sql`](supabase-wishes.sql)，整段複製貼上，按 **Run**。
3. 看到成功訊息即可。這一步只需要做一次。

## 三、關閉公開註冊（很重要）

左側 **Authentication** → 設定頁（Sign In / Providers 或 Settings），把 **Allow new users to sign up**（允許新使用者註冊）**關掉**，按儲存。

權限規則是「登入的人都能讀留言」，如果不關掉，任何人自己註冊一個帳號就能讀到。

## 四、建立兩個製作者帳號

左側 **Authentication** → **Users** → **Add user** → **Create new user**：

- 輸入 email 與密碼，勾選 **Auto Confirm User**（自動確認）。
- 你和協作者各建一個。密碼各自保管，**不要貼給 AI 助理**。

## 五、把兩樣東西貼給 AI 助理

左側 **Project Settings** → **API**（或 **Data API**／**API Keys**）：

| 要貼的 | 長什麼樣子 |
|---|---|
| Project URL | `https://xxxxxxxx.supabase.co` |
| 公開金鑰 | 標示 **publishable**（`sb_publishable_…`）或 **anon public** 的那一把 |

這兩個是設計上可以公開的資料，會寫進 `src/wish-config.js`。

**絕對不要貼、也不要放進倉庫的**：

- `service_role` 或 `secret` 金鑰
- 資料庫密碼
- 製作者帳號的密碼

## 六、設定完成後

- 遊戲：玩家在廣場的許願池按「送出」，留言就會存進 Supabase。
- 願望紀錄頁：打開網站的 `wishes.html`（遊戲裡沒有連結），用製作者帳號登入，可以看留言、標記已讀、刪除、匯出成 CSV。

## 權限規則一覽

| 身分 | 新增 | 讀取 | 修改 | 刪除 |
|---|---|---|---|---|
| 一般訪客（未登入） | 可以，只能填留言文字 | 不行 | 不行 | 不行 |
| 登入的製作者 | — | 可以 | 只能改「已讀」 | 可以 |

## 需要知道的限制

- **每 30 秒最多送一則**是在玩家的瀏覽器裡限制的。有心人可以繞過網頁直接送留言，資料庫擋不住；如果收到垃圾訊息，在願望紀錄頁刪除即可。
- **免費專案閒置太久可能會被暫停**，需要到 Supabase 手動恢復。暫停期間玩家會看到「這次沒有送成功」，不影響遊戲。實際規定請以 Supabase 方案說明頁為準。
- **Supabase 的伺服器紀錄**可能會記下連線的 IP 位址等技術資訊；遊戲本身不會送出任何身分資料。
- 願望紀錄頁的保護靠的是登入與資料庫權限，不是「網址沒人知道」。網址被猜到也只會看到登入畫面。
