# 內容編輯說明

遊戲裡的文字都放在 `content/` 的 JSON 檔，程式只負責讀取與呈現。改完存檔、重新整理瀏覽器就能看到。

> JSON 很在意格式：字串要用半形雙引號 `"`，項目之間要有逗號，最後一項後面不能有逗號。改壞時遊戲首頁會顯示「遊戲內容載入失敗」。可以先貼到 <https://jsonlint.com> 檢查。

所有心理健康相關文案都是**衛教草案**，正式對外使用前須經心理專業審閱（企劃書 7.2 節）。修改時請遵守 AGENTS.md 第 5 節的衛教內容原則。

## 檔案一覽

| 檔案 | 內容 |
|---|---|
| `quest.json` | 主線任務的步驟、每一步的目標文字、必要卡 |
| `characters.json` | 曉晴、阿德：姓名、介紹、外觀顏色、站的位置、依任務步驟與記號選擇的對話 |
| `places.json` | 三個區域（文字模式的地點說明）、互動物件（公布欄、便條、風鈴、長椅）與謎題入口 |
| `dialogues.json` | 所有對話 |
| `cards.json` | 六張理解卡 |
| `card-uses.json` | 用卡互動：哪張卡可以在哪裡、哪個任務階段使用，以及不適用、缺卡時的提示 |
| `minigames.json` | 兩個練習的文案 |
| `puzzles.json` | 兩個謎題：線索、位置、答案、答錯時的線索方向、解開後的說明 |
| `hints.json` | 橘貓麻糬：可以問的題目與三層提示的文字 |
| `music.json` | 背景音樂：各區域的曲目、授權、淡入淡出秒數、練習時的音量比例 |
| `resources.json` | 「找支持」面板的現實資源 |

## 常見修改

### 改一句台詞

在 `dialogues.json` 找到那句話，直接修改 `text`。`speaker` 是說話的人；`"旁白"` 不顯示名牌，`"你"` 代表玩家。

### 對話的結構

```json
"muyu.meet.event": {
  "lines": [
    { "speaker": "曉晴", "text": "第一句" },
    { "speaker": "曉晴", "text": "第二句" }
  ],
  "effects": [ { "setFlag": "某個記號" } ],
  "choices": [
    { "text": "選項一", "next": "下一段的名稱" },
    { "text": "選項二", "effects": [ { "openResources": true } ] }
  ]
}
```

- `lines`：依序顯示的台詞。
- `next`：沒有選項時，接著播放的下一段。
- `choices`：最後一句之後出現的選項；選項沒有 `next` 就結束對話。
- `effects`：整段顯示完（或按下選項）時發生的事。可用的效果：

| 效果 | 說明 |
|---|---|
| `{ "giveCard": "K01" }` | 給一張理解卡（已經有就不重複給） |
| `{ "advance": { "from": ["步驟"], "to": "步驟", "then": [效果] } }` | 目前在 `from` 列出的步驟時，任務前進到 `to`，再觸發 `then` |
| `{ "setFlag": "名稱" }` | 記下一個記號（例如已確認過） |
| `{ "minigame": "thought" }` | 對話結束後開啟練習（`thought` 想法放大鏡、`present` 回到這座花園）；要親手完成才觸發練習的 `onComplete` |
| `{ "openResources": true }` | 打開「找支持」 |
| `{ "openCardbook": true }` | 對話結束後打開卡冊 |
| `{ "dialogue": "名稱" }` | 對話結束後接著播放另一段 |

**發卡和任務前進要放在同一組 `effects` 裡**，遊戲會一起儲存，避免拿到卡卻沒推進任務。

### 角色在不同階段說不同的話

`characters.json` 的 `talk` 由上往下比對 `when` 條件，用第一個符合的對話：

| 條件 | 意思 |
|---|---|
| `"step": ["thought", "clarify"]` | 任務在其中一個步驟 |
| `"stepFrom": "wrap"` | 任務已經走到這一步或之後 |
| `"flag": "名稱"` ／ `"notFlag": "名稱"` | 有／沒有某個記號 |
| `"card": "E01"` | 持有某張卡 |

最後一項不寫 `when`，當作預設對話。

### 改理解卡

`cards.json` 每張卡都有：`title`（卡名）、`keyPoint`（一句重點）、`description`（說明）、`example`（故事例子）、`obtain`（取得途徑）、`hint`（未取得時顯示的線索）、`useHint`（使用提示）、`sources`（來源連結與查核日期）、`review`（審閱狀態）、`updated`（更新日期）。

- **卡號（`id`）不要改**，進度與用卡互動都靠它。
- 審閱完成後，請更新 `review` 與 `updated`。
- `icon` 可用：`hands`、`magnifier`、`leaf`、`door`、`chair`、`cloud`（插圖畫在 `src/cards.js`）。

### 用卡互動

`card-uses.json` 的每一筆：`target`（角色或物件 id）、`card`（卡號）、`steps`（可用的任務步驟）或 `fromStep`（從這一步起都可用）、`intent`（選卡後顯示的「打算怎麼做」）、`dialogue`（成功時播放的對話）。

- `tooEarly`：卡對了、但時機還沒到時的提示。
- `missing`：缺少必要卡時的取得指引（也會顯示在左上角的任務目標下方）。
- 卡片使用後一律保留，不會消耗。

### 謎題

`puzzles.json` 的每個謎題有：`intro`（開場說明）、`slots`（可以放的位置，`icon` 用形狀符號，不只靠顏色）、`items`（要擺放的東西：`clues` 線索、`answer` 正確位置、`hint` 答錯時的線索方向）、`solved`（解開後的說明）。

- `hint` 只說「看哪個線索」，**不要寫出答案，也不要評價玩家**。
- 每條線索都要有文字；不要只用顏色或聲音當唯一線索。
- 線索要在同一區域內找得到，不需要遊戲外的知識。
- 入口物件寫在 `places.json`（`"puzzle": "E01"`），3D 的擺設在 `src/three/world.js`。

### 麻糬的提示

`hints.json` 的 `layers` 是三層提示的文字（`{area}`、`{name}` 會換成區域與物件名稱）。提示的目標自動取自目前任務的 `target` 與謎題的 `entry`，不用另外設定。

### 背景音樂

1. 把音檔放進 `assets/audio/`（建議 mp3 或 ogg，每首 3 MB 以內，可循環）。
2. 在 `music.json` 的 `tracks` 填上區域對應的曲目，例如：
   ```json
   "plaza": { "file": "assets/audio/plaza.mp3", "title": "曲名", "author": "作者", "url": "來源頁面", "license": "授權名稱", "licenseUrl": "條款網址" }
   ```
   三區想用同一首時，填在 `default` 就好。
3. 在 `docs/素材來源.md` 的表格記錄同樣的資訊。只用 CC0 或授權明確允許免費使用的曲子。

### 現實資源

`resources.json` 只填官方來源可以確認的資訊，不確定的寫「請洽官方確認」，**不要自行猜測**。每筆都要有 `url`（官方來源）與 `checked`（查核日期）。政府年度方案請填 `validYear`（西元年），超過後面板會自動標示「本年度內容待更新」。

建議每月查核一次資源連結，年度交替或政策異動時提前更新；心理衛教內容每季檢視（企劃書 5.3 節）。

## 新增角色或場景時

角色與關卡依人物、場所與生活事件組織，**不要用疾病為地圖或人物命名、配色或分類**，也不要在名牌旁加疾病標籤（企劃書 2.3 節）。新增角色需要同時改：

1. `characters.json`：角色資料與對話入口。
2. `dialogues.json`：對話內容。
3. `src/three/world.js`：如果站的位置附近需要擺設或碰撞。
